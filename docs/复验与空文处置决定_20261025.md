## 九、空文定性：不是漏抽，是投票/微文/图片贴（2026-10-25 21:55–22:15）

### 起因
主线 21:43 重新起轮后，空正文产物从 67 篇涨到 **154 篇**（21 时单小时新增 21 篇），
样本标题却是"周三会拉大阳吗""下午会拉抬什么股"这类**每日股评**，一度怀疑是解析器
在 2010 年后模板上把成段正文丢掉了（即静默数据损失）。

### 逐篇核对（154 篇全量，读 raw 快照）
用 `temp/classify_empty.py` 与 `temp/probe_missing.py` 对每篇取出正文容器内的纯文本：

| 类别 | 篇数 | 说明 |
|---|---|---|
| 投票贴 | 80 | 正文即投票控件（"发起时间/截止时间/投票人数"）+ 一句话 |
| 微文贴 | 54 | 容器内仅 20~38 字一句话，常带"文章引用自：" |
| 图片贴 | 20 | 容器未命中或无 raw（标题如"最揪心的5张灾区图片""股指技术分析图"） |
| **容器内文本 >120 字的（真漏抽）** | **0** | 最长仅 38 字 |

**结论：没有任何一篇存在被丢弃的成段正文**，先前的怀疑不成立。这类帖子是博主
用投票/一句话/配图发的短贴，容器内文本上界只有 38 字。

### 但确有真实损失：那句唯一的话被丢了
解析器把 <30 字的正文整段丢成 0 字，于是这些帖子连**唯一的一句话**也不见了。
新增离线工具 `tools/fill_micro_text.py` 补回（不动解析器、不影响在跑的抓取）：

```

```

新增字段 `body_source: micro`、`micro_chars: N`；备份 104 份；复核 frontmatter 异常 0。
例：`48874cec01008on9` 补回"关注14:00--14:30后的技术拐点 仅供参考!"。

### 口径修正（重要）
