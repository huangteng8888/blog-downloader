## 二、定位到的三个真实缺陷（关键发现）

### 1. 旧模板容器是 `id` 而非 `class`
2006–2008 年的新浪博客用的是元件化旧模板：

```html
<a id="articleTitle">3720/3750区间完成二次探底…</a>
<span id="articleTime" class="sun icon textIcon">2007-07-02 13:55:01</span>
<div id="articleBody" class="articleContent">…正文…</div>
```

而原解析器只认新模板的 `class="articalContent"`，命中不了旧模板 → 标题回退到 `<title>`（
于是出现大量《wu2198 - 新浪BLOG》这类假标题）、正文取空。

### 2. 非贪婪正则在嵌套 div 上"提前截断"（最主要原因）
即使命中容器，这种写法：

```python
r'<div[^>]+class="articleContent[^"]*"[^>]*>(.*?)</div>\s*(?:<div|<!--)'
```

遇到正文首行的 `<div><font>…</font></div> <div>` 就立刻停止匹配，只截到十几个字符，
被长度阈值判为"无正文"。

实测对比（同一份已存快照）：

| 文章 | 旧解析器 | 新解析器 |
| --- | --- | --- |
| 48874cec01000bto《价值投资的三要素》 | 0 字（判为无正文） | **4,845 字** |
| 48874cec01000c03（2007-07-02 股评） | 0 字 | **1,187 字** |
| 48874cec01000eya《六类股票 节后最危险》 | 0 字 | **1,430 字** |

修复方式：先用优先级列表定位正文容器起始下标，再做 `div` 标签配平扫描找结束位置，
最后用 `articalTag / articleBottom / commentList` 等页脚标记兜底截尾。

### 3. 部分快照为 GBK 字节被当 UTF-8 解出
表现为 `璇峰叧娉ㄥ北鍖虹殑瀛╁瓙`（应为"请关注山区的孩子"）。已在正文与标题上
加 `gb18030 → utf-8` 反向修复，并对正常中文无副作用（已用 5 组样例验证）。

## 六、补抓脚本使用方式（断点续跑）

```bat
cd /d D:\cursor_test\blog-downloader
python tools\wayback_resume.py --seconds 10800 --gap 15
```

| 参数 | 作用 |
| --- | --- |
| `--seconds` | 本轮运行时长（秒），到时自动优雅退出，进度已落盘 |
| `--gap` | 篇间隔，默认 15 秒（≈3.4 篇/分钟），**不建议再调低** |
| `--limit` | 本轮最多抓取篇数 |
| `--max-fail` | 连续临时失败阈值（含 429 限流）触发熔断退出 |
| `--shuffle` | 打乱抓取顺序 |

特性：
1. **断点续跑**：已落盘的文章自动跳过，中断后重跑即从断点继续；
2. **限流熔断**：反代返回 429/异常时连续计数达标即停止，避免触发封禁；
3. **账号轮换**：4 个公开 CORS 反代节点轮换，单点在途请求数恒为 1；
4. **失败分类**：`permission`（源站私有）/ `encrypted`（加密博文）/ `no_body` / 网络临时失败，
   只有确认不可恢复的才写入 `permanent_fail.json`。
