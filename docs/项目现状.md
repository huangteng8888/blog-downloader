## 一、核心结论

本次排查定位到**一条根因连锁**，并已全部修复：

`src/runner.py --rebuild-index`（灾难恢复模式）从单篇 `.md` 重建 `index.json` 时，
v2 的单篇 md frontmatter **只有 `article_id`**、正文也不含时间与作者信息，因此
`pub_time` / `author_uid` / `author_name` / `timestamp` 被**静默清空**。而真正的元数据
本就存放在 `index.json` 中 —— 从 md 反推索引，等于自我毁灭。

由此引发的三个表面症状（均已消除）：

| 症状 | 修复前 | 修复后 |
|---|---|---|
| ① 知识图谱退化 | 徐小明图谱仅 **171 条边** | **77,062 条边** |
| ② 打分时间字段全空 | 缺失率 93.6%~100% | **0%**（top500） |
| ③ 时间维度检索失效 | `date_index` 基本为空 | 时间跨度已恢复 |

**修复的三个关键支点**（均为本次实测发现）：

1. 根目录 v1 旧数据保留了 `published_at` / `author_name` / `tags`，是元数据恢复的唯一来源；
2. **v1 的 hash 文件名 = `md5(文章URL)`**（20/20 命中），使 v1 图谱中只有 hash 的记录
   也能反向关联 `article_id`，据此救回股市风云；
3. 详情页仍可直接读取发布时间，最后 251 篇通过定向重抓补齐。

## 四、遗留事项

### 4.1 16 篇文章时间不可恢复（0.08%）

徐小明 13、股市风云 3。已重试并直接校验 HTTP 状态码：源站返回 `404 page not found`，
即文章已被新浪删除。**无任何技术手段可恢复**，建议接受。
进度文件 `.backfill_sina_progress.json` 已记录这些条目，不会重复尝试。

### 4.2 股市风云 `author_name` 97.4%

其 v1 图谱只含 7,094 个 post 节点，剩余 190 篇无从获取作者字段（不影响使用，单博主数据）。

### 4.3 打分的残余长度偏置

徐小明 top500 仍有 22.6% 不足 150 字，属该博主大量产出"每日一句话"点评的行文风格；
分母效应（1/len）已由 `sqrt` 归一化消除。若下游需要纯理论长文，建议在筛选阶段
追加 `text_len` 阈值，而非继续加重打分惩罚。

### 4.4 跨博主得分不可比

三人词表规模、文章长度分布差异大，`raw_score` 只在**同一博主内**有序。
跨博主比较应使用排名或分位。

### 4.5 keyword 节点未生成

当前图谱不含 `keyword` 节点，与重建前的 v2 图谱结构等价、体积可控。如需要：
`python tools/rebuild_graphs.py --with-keywords`（较慢；务必保留已修复的关键词抽取逻辑，
否则会重演 2 GB 膨胀）。

### 4.6 工程化

- 项目**无 git 仓库**，本次改动无法用 diff 追溯，建议 `git init` 并提交当前基线；
- 抓取依赖新浪页面结构，`class="time"` / `class="titName"` 等正则可能随改版失效。

## 六、复发预防清单

1. **执行 `--rebuild-index` 前**：确认 `posts/index.json.bak` 存在；该模式现已自动备份并告警，
   但仍不建议在缺少 `legacy/` 数据源时使用。
2. **不要删除 `legacy/`**：它是元数据恢复的唯一来源（含 23 篇 v2 缺失文章）。
3. **改动图谱或打分后**：运行 `tools/health_check.py`，确认 `pub_time` 覆盖率未回落。
4. **警惕图谱体积**：`knowledge_graph.json` 超过 100 MB 通常意味着又出现了完全图或整句关键词。
5. **改动存储/元数据后**：运行两个测试命令（见 README）。
6. **补数据时只用权威来源**：正文里"看起来像日期"的字符串往往是 `fetched_at`
   或链接中他文的日期，会污染数据集。
