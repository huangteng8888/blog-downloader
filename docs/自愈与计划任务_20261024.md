| 抓取进程 | 剩余篇数 | 进度日志年龄 | 动作 |

## 四、过程中的三个自身缺陷/误判（如实记录）

1. **把 `timeout.exe` 的报错误判为 wscript/pythonw 的问题。**
   我看到 stderr 的 `ERROR: Input redirection is not supported` 就断定"VBS 启动方式不可用"，
   实际上那是 `timeout.exe` 在管道 stdin 下的报错 —— 意味着我那些"等待 8/10/15 秒"
   **从未真正等待**，日志检查跑得太早，据此得出的"失败"结论不成立。
   更正：改用 `Start-Sleep` 等待后重测，pythonw 链路一次通过。vbs 已弃用（多层包装没必要），
   但**先前那条"vbs 不可靠"的判断是错的，属误诊**。
2. **`.bat` 中文注释在 GBK 代码页下被 cmd 当作命令执行**（stderr 出现 `'愈巡检启动器（由' is not recognized`）。
   cmd 按 OEM 代码页读取批处理，UTF-8 中文注释会被拆坏。已改为**纯 ASCII 注释**，重测 stderr 干净。
   该缺陷当时并未影响 python 那行执行，但属于应该避免的坑。
3. **`remaining()` 口径错误，且后果严重。** 清单文件 `temp/wayback_cdx2.json` 是**嵌套字典**
   （文章在 `"items"` 键下，顶层仅 3 个键），我按"整个文件的长度"相减，算出"剩余 -1486/-1890 篇"。
   若采信这个负数，一旦抓取真的停滞，自愈会判定"已全部处理完"而**拒绝重启** —— 等于亲手关掉自愈。
   已改为照抄 `tools/wayback_resume.py` 的加载方式（`load_json(LIST_FILE).get("items")`），
   并额外增加负数降级保护；另需说明：**该修正曾因本轮会话流中断丢失过一次**，
   经独立复算确认现已真正生效。


需要停止时（**顺序很重要**）：

```bat
rem 1) 先立停止旗标，让巡检不再自动拉起
echo stop > output\1216826604_wayback\STOP

rem 2) 再禁用计划任务（保留任务定义，便于日后恢复）
schtasks /change /tn "FxzBlogCrawler-SelfHeal" /disable

rem 3) 最后结束守护与抓取进程（守护 PID 见 progress 同目录 watchdog.pid）
```

收尾检查：`heal_status.json` 中 `remaining` 为 0，且连续数轮巡检 `posts` 不再增长，
即可判定补齐工作完成；此时 `ALERT.md` 中不应有新条目。
