## 二、根因：探测失败被当成"没有进程"（fail-open）

守护脚本原实现：

```python
def crawlers():
    try:
        out = subprocess.run(["powershell", ...], timeout=60).stdout or ""
    except Exception:
        return []          # ← 查询失败返回"空列表"
    return [l for l in out.splitlines() if CHILD_KEY in l]
```

调用处 `if ext: 等待接管 else: 启动新一轮`。于是**任何一次查询抖动**（PowerShell 启动失败、
WMI 偶发不可用、编码异常导致解码出空串）都会被读成"当前没有抓取进程"，直接导致重复启动。

这是一个方向性错误：**"查不出来"必须表示"不知道"，绝不能表示"没有"。**
对于"绝对不能重复执行"的动作，默认答案只能是"不做"。

## 四、修复内容

### 4.1 守护脚本 `tools/watchdog_run.py`（核心修复）

1. 新增 `_ps_python_cmds()`：枚举全部 `python.exe` 的 `(pid, 命令行)`，任何异常/非零退出码 →
   返回 `None`（不可信），不再返回空列表。
2. 新增 `probe()`，返回三态：
   - `yes` 有抓取进程 → 等待接管
   - `no` 确认没有 → 允许启动
   - `unknown` 无法确认 → **按"有"处理，拒绝启动**（fail-closed）
3. **枚举自检**：结果中必须能看到守护自身 PID，否则说明枚举不完整 → 归为 `unknown`。
4. **交叉验证**：新增 `log_age()`，读 `progress.log` 的写入时间。若进程枚举说"没有"、
   但进度日志 30 秒内刚被写过 → 两个信号矛盾 → 拒绝启动。
5. 查询失败重试 3 次（每次间隔 3 秒）后才判定 `unknown`，避免瞬时抖动直接放大成决策。

### 4.2 补丁器 `tools/apply_resume_patch.py`（同类隐患）

- `crawlers()` 同样改为"失败返回 `None` + 自检自身 PID"；等待循环遇 `None` 时**继续等待**并记日志，
  绝不因探测失败而提前动手。

## 五、加固后的行为契约

- 只有**明确确认没有**抓取进程时，守护才会拉起新实例；
- 探测不可信、信号矛盾、查询失败 → 一律等待，宁可空等一轮，不可重复启动；
- 每轮启动前的探测结果、等待原因均写入 `watchdog.log`，事后可审计；
- 探测逻辑自检（自身 PID 必须出现在枚举结果中），避免"静默返回空集合"这类最危险的失败模式。
