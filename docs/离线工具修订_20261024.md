## 1. `tools/verify_digest.py` —— 字节校验 v2

### 问题
原版只对**网络取回的字节**做校验、且样本硬编码为 2 篇；并且没有统一处理反代的
JSON 信封（`{"content": "..."}`），一旦命中信封路径就必然 SHA1 不匹配，
容易被误读为"内容被篡改"（本次会话已踩坑：一度误判"15 篇容器未命中"）。

### 修订
| 项 | 内容 |
|---|---|
| 新增统一解包入口 | `wayback_resume.unwrap_delivered(b)` 返回候选字节形态：`原始字节` / `JSON.content(utf-8 重编码)` / `JSON.content(latin1 还原)` |
| 默认模式（离线） | 扫描本地 `raw/*.gz`，与 front-matter 记录的 `raw_sha1_b32` 逐篇比对；对信封产物额外给出**解包后 digest**，供与 CDX 进一步比对。零网络请求 |
| `--cdx N`（在线） | 抽样 N 篇（默认 3），间隔 **15 秒**（遵守限速），向 CDX 查询 digest 后逐一尝试三种字节形态 |
| 退出码 | 存在不一致时返回 1，便于挂到巡检脚本 |

### 结果

```
### 离线字节校验（raw/ 本地存档）
  存档文件      : 298        <- 随抓取进行持续增长
  与记录一致    : 298
    └ 其中 JSON 信封 : 78
  **与记录不符** : 0  (须为 0)
  无记录 hash   : 0
```

报告：`integrity/digest_verify_local.tsv`（含每篇的原始 envelope digest 与解包后 digest）。

**意义**：归档环节的字节完整性现在可以随时离线自证，不再依赖联网抽样。

## 2. `tools/quality_alarm.py` —— 正文质量告警口径 v2

### 问题
旧口径按**纯长度**告警（`<60 字`、`60-200 字`），会把博主的一句式真实短文
（股票名单、单句点评）误报为缺陷。实测 12 份有 raw 存档的样本：
**容器纯文本 ≈ 落盘正文**（55/35、210/155、108/97、61/55），差异仅 `&nbsp;`
—— 即没有"被我们丢掉的正文"，是源站内容本就短。

### 修订（先剔残留，再按结构判定）
| 分类 | 判定 | 动作 |
|---|---|---|
| `full` | 剔除残留后 ≥200 字 | 无需动作 |
| `thin_real_short` | 剔除残留后 <200 字的真实短文 | 进入**抽样复核清单**（非缺陷） |
| `title_date_residue` | 只剩标题/日期/转载等模板残渣 | **建议重抓重解析** |
| `empty_body` | 正文为空（纯图片博文） | 无需动作（已正确标记） |

残渣判定含两级：① 全部行都是日期行/模板词/标题行；② **增强判定**——
短正文中出现 `YYYY-MM-DD HH:MM` 且移除标题、日期、`转载/转帖/转自/引用/分享`
与标点后所剩不足 8 字（捕获旧模板"标题与日期同行"形态）。

### 结果

| 分类 | posts/（845 篇，含未清洗，随抓取增长） | clean/（724 篇） |
|---|---|---|
| `full` | 707（83.7%） | 605（83.6%） |
| `thin_real_short` | 116（13.7%） | 97（13.4%） |
| `title_date_residue` | 1 → **6**（口径修正后，3 次复测稳定） | **6**（0.8%） |
| `empty_body` | 16（1.9%） | 16（2.2%） |
| 残留模板标记 | 642（待清洗，已由 clean/ 承接） | **0** |

## 3. 本轮踩到的工具缺陷（已修）

| 缺陷 | 影响 | 处置 |
|---|---|---|
| `make_clean_copies.py` reparse 分支误将正文置空 | 首次运行写出 177 篇空正文副本（台账显示删除 218,194 字），若不核对会直接污染副本 | 已修；重跑后删除量回归合理值 4,533 字 |
| `quality_alarm.py` 明细行只在"含残留"时记录 | 报告表的明细为空，只有汇总数字 | 已修；改为记录所有 `action != none` 的条目 |

> 教训：**批量写入类脚本必须自带"删除量/长度分布"量级校验**，
> 否则异常值（218,194 vs 4,533）很容易被当成正常输出。
