1. 这是一条**新浪博客 → Markdown 知识库 → 知识图谱 → 关键词/打分**的离线数据生产流水线，服务下游「教你炒股票」类知识提取。

## 二、项目定位与数据流

```
① 列表发现        src/spider.js (Playwright, JS 渲染页) / 专用采集器
        ↓
② 正文抓取        src/spider.py (curl + Cookie 绕 418，断点续跑/增量)
        ↓
③ 落盘            src/storage.py → output/{uid}/posts/{article_id}.md（frontmatter 仅 article_id）
        ↓
④ 元数据          src/metadata.py → metadata.json + posts/index.json（唯一权威元数据）
        ↓
⑤ 知识图谱        src/blog_graph.py (networkx) → knowledge_graph.json
        ↓
⑥ 关键词发现      keyword_analyzer.py (jieba TF-IDF) → keyword_discovery/stock_keywords_v1.json
        ↓
⑦ 打分筛选        post_scorer.py → keyword_discovery/scored/{uid}_ranked.json / _top500.json
```

**核心设计取舍**：所有元数据集中在 `index.json`，单篇 md 只留 `article_id`，避免同字段两处存储不一致。
代价是：**从 md 反推索引必然丢元数据**（见第六节根因 1）。

## 六、历史根因与已完成的修复（务必保留的认知）

**根因连锁**：`runner.py --rebuild-index` 从 md 反推索引，而 v2 单篇 md 只有 `article_id` → `pub_time`/`author_name`/`timestamp` 被静默清空 → 图谱退化（徐小明仅 171 条边）、打分时间字段缺失 93.6%~100%、时间维度检索失效。

关键支点（实测发现）：
1. v1 旧数据保留 `published_at`/`author_name`/`tags`；
2. **v1 的 hash 文件名 = `md5(文章URL)`**（20/20 命中），使只有 hash 的 v1 图谱记录也能反推 `article_id`；
3. 详情页 `<span class="time">` 仍可直读，最后 232 篇靠定向重抓补齐（成功 216、404 失败 16）。

关键代码修复（18 项，摘要）：
- `metadata.rebuild_from_files()`：自动备份 `index.json.bak` + 存续映射回填 + 覆盖率 <50% 告警；
- `blog_graph._add_tag_edges()`：标签两两连边改为 **tag 枢纽 O(n)** + 仅低频标签（≤20 篇）保留 `shares_tag`（原「股票」标签会生成约 7,500 万条边）；
- `blog_graph._extract_keywords()`：整句当关键词 → jieba + 停用词/词长过滤（原会产出 2.15GB 图谱）；
- `post_scorer`：分母 `1/len` → `1/sqrt(len)`；`date` 改从 `index.json` 读取（原从正文正则取，会把 `fetched_at` 当发布时间）；
- 所有脚本去掉 `/mnt/data`、`/tmp` 固定绝对路径，改按脚本目录解析并支持 `BLOG_DOWNLOADER_ROOT` 覆盖。

**来源可靠性甄别（重要经验）**：
✅ 采用 —— legacy md frontmatter、v1 图谱 post 节点、v1 索引、analysis_results、详情页 `span.time`；
❌ 否决 —— md 正文正则取日期（命中 `fetched_at`）、旧打分产物 `date`（目录页链接日期被误当发布日期）。

## 十、复发预防清单

1. **执行 `--rebuild-index` 前**确认 `posts/index.json.bak` 存在；缺 `legacy/` 时禁止使用。
2. **不要删除 `legacy/`**（唯一元数据恢复源，含 23 篇 v2 缺失文章）。
3. 改动图谱或打分后**必跑 `health_check.py`**，确认 `pub_time` 覆盖率未回落。
4. `knowledge_graph.json` 超过 **100MB** 通常意味着又出现完全图或整句关键词。
5. 补数据**只用权威来源**；正文里"看起来像日期"的字符串往往是 `fetched_at` 或他文链接日期。
6. supplement 的 297 篇 `unverified/` **不要与原博客 2404 篇混库**（转载被删改、标题被改写）。
7. wu2198 主页/列表/正文页均可能被博主权限拦截，抓取必须走 `article_sort` 列表接口与专用采集器。
